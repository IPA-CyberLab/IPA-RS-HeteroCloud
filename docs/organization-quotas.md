# アカウントとメンバーのリソース上限

利用者は「アカウントと組織」から新しい組織と管理アカウントを作成し、管理アカウント内からメンバーアカウントを作成できます。上部のアカウントメニューで操作対象を切り替えられます。既存ユーザーも招待コードから別のアカウントに参加できます。

運営が設定する従来の「組織ごと」の上限は、それぞれのアカウントの上限として引き続き適用されます。アカウントのオーナーと管理者は「リソース上限」で全メンバーの適用上限を確認し、メンバーごとの上限を設定できます。一般メンバーには自分の上限だけを表示します。管理者の任命・解除はアカウントオーナーのみが行えます。個人上限はAWS Service Quotasとは異なるHeteroCloud固有の機能です。

メンバー上限は予約ではなく、個人とアカウントの両方の上限を満たす必要があります。アカウントの上限を引き下げた場合、個人の実効上限もその値を超えません。Flashの週次 CPU、メモリ、GPU はアカウント全体とメンバー単位の両方で集計され、いずれかの上限に達すると対象サービスが停止し、上限の引き上げか次の週まで再開されません。週の境界は月曜 00:00 UTC です。OUや組織全体を合算する上限はありません。

既存のサービスやサービスアカウントの持ち主を信頼できる記録から判定できないときは、「割り当て先が未設定」に表示します。組織管理者は、それぞれ適切なメンバーを選んで割り当ててから個人別上限を設定してください。サービスアカウントから作られたサービスは、そのアカウントに割り当てられたメンバーの上限に計上されます。Flashワークロードから作成した子サービスは、親サービスのメンバーに計上されます。

Flash Registry の保存容量と認証情報数、Syouyu の認証情報数は組織で共有されるため、現時点では組織単位の上限です。過去の使用量について持ち主を判別できないものは個人の使用量として推測せず、組織全体の使用量に含めます。
