# VPCと外部公開の検証（2026-10-04 UTC）

**E2E全体は未合格です。** 主要な通信検証は通過しましたが、VPC削除後の状態確認で公開APIがHTTP 503を返し、本体・設定例の両方が失敗判定になりました。結果を成功へ書き換えていません。503の原因は未特定です。

## 確認できた動作

HeteroCloud / CLI 0.1.93、Flash 0.1.41、VPC 0.1.3の稼働環境を使用しました。実装済みの公開機能とVPCの併用を確認しており、今回ランタイムの変更はありません。

- API / CLIからのVPC操作、親コンテナからの非公開な子の作成。
- VPC内のTCP / UDP通信は既定で拒否し、許可したサービス・グループとポートだけに接続できること。
- 別グループ・別VPC・別組織への通信拒否、グループ接続のIAM制限、子へのAPIキーの非継承。
- NATの有効化・無効化と、Flashの送信禁止設定が効くこと。
- NATと送信を無効にしたまま、選んだVPC内のサービスだけへ外部からHTTPS接続できること。
- 公開してもVPC内通信には明示的な許可が必要なこと。
- 外部公開を解除するとHTTP 404 / 421となり、許可したVPC内の新しい接続は成功すること。
- コンソールの表示がPCで1,598 ms、モバイルで1,491 msと3秒以内だったこと。

本体は24チェックを通過後、最後の削除確認で失敗しました。追加の[公開設定例](../../examples/cli/flash-vpc-public.json)は、nginxをCLIで作成し、APIが返すHTTPS URLで200とnginxの内容を確認、非公開へ戻した後に同じURLが404 / 421となる3チェックを通過しました。この追加試行も最後の削除確認で503となりました。

設定例の初回はDocker Hubからのイメージ取得がTLSハンドシェイクのタイムアウトで失敗しています。稼働ノードからのレジストリ接続を確認した後、設定を変えずに再試行し、上記のHTTPS検証まで通過しました。

## 未解決事項と回収結果

公開APIの503は、本体と設定例の削除ポーリングに加え、補助監視の一覧取得でも観測しました。その後の12回のAPI参照は200でしたが、これだけで解決したとは判断していません。

失敗後にAPIで後片付けを再実行し、KubernetesとDBを別途確認しました。テスト用のPod・Deployment・Service・PVC・NetworkPolicy・ServiceAccount・Flash・VPC・EgressPolicy・EgressGateway・Namespaceは残っていません。4つのテスト組織、APIキー、ブラウザー用ユーザーとセッションも削除済みです。Cloud・Flash・VPC・VPC egressのArgo CD ApplicationはSynced / Healthyでした。
