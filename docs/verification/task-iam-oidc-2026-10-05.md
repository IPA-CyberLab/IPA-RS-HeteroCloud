# タスクIAM・任意OIDC認証の実環境検証 — 2026-10-05

Flashの作成・編集画面、API、CLIから、同じ組織のサービスアカウントをタスクIAMとして指定できる。コンテナ内のCLIはPodに紐づく更新可能なJWTを使い、15分有効なHeteroCloudトークンを取得・更新する。個人用CLIログインや固定APIキーを親コンテナへ渡す必要はない。

IAM管理APIもCLI OAuth認証に対応し、サービスアカウント・ポリシー・割り当ての管理、アカウント無効化、専用キーの発行・失効をCLIから操作できる。ロールの付与と専用キーの発行には `iam:PassRole` を要求する。APIリクエストでは現在のIAMポリシー、サービスのロール、アカウントの有効状態を確認する。親の権限は子へ自動継承しない。

HTTP/HTTPSのFlashロードバランサーでは、サービスごとに「認証なし」または「OIDC」を選択する。既定は認証なし。OIDCのIssuer、Client ID、シークレット参照を設定し、APIが返すコールバックURLをIdPへ登録する。シークレット欠落やポリシー未受理時はアプリケーションへの転送を遮断する。

利用手順は [タスクIAM](../iam/workload-identity.md) と [ロードバランサー認証](../networking/load-balancer-oidc.md) を参照。

## 配置と検証

HeteroCloud **v0.1.102**、Flash **v0.1.46**、Envoy Gateway **v1.8.4** をTerraform管理のArgo CD Applicationから配置した。イメージはリリース成果物のダイジェストに固定した。3つのApplicationは `Synced / Healthy`、今回の変更範囲を対象にした最終Terraform planは差分なし。

[HeteroCloudのリリースCI](https://github.com/IPA-CyberLab/IPA-RS-HeteroCloud/actions/runs/37297972744) と [FlashのリリースCI](https://github.com/IPA-CyberLab/IPA-RS-HeteroCloud-Flash/actions/runs/37297508349) は成功した。HeteroCloudではAPI・ドメイン・CLI、実PostgreSQLでのIAM/OAuth統合テスト、コンソール検証、Linux・macOS・Windowsのx64／ARM64成果物を検証した。Flashではコントローラー、生成CRD、シークレット用ランチャー、イメージを検証した。

実環境のタスクIAM検証は9項目を通過した。親コンテナへ検証済みCLI 0.1.102だけをコピーし、APIキー・個人ログインを設定せず、VPC内にgVisorの非公開子コンテナを作成・削除した。未許可のIAM操作、組織をまたぐ操作、`iam:PassRole` なしのロール付与を拒否した。アカウント無効化で発行済みトークンと新規交換を拒否し、再有効化後も古いトークンは復活しなかった。ポリシー割り当て解除も稼働中の親コンテナに反映された。

実際のIdP・Gateway・アプリケーションを使うOIDC検証は11項目を通過した。Chromiumのデスクトップとモバイル画面サイズで、ログイン、元URLへの復帰、Secure／HttpOnly／SameSite=Laxかつホスト限定のCookie、ロードバランサーのログアウトを確認した。シークレット欠落、不正なIssuer、使用中シークレットの削除拒否、設定の復旧、認証なしへの切り替え、準備中の固定レプリカサービスからのコールバックURL取得も確認した。認証設定を繰り返し変更したアプリケーションPodのUIDと再起動回数は変わらなかった。

コンソールは実APIに接続し、タスクIAMの選択、任意OIDCの設定、空のシークレット欄、アカウント無効化・割り当て解除の操作表示を確認した。最終表示時間はデスクトップ **1,257 ms**、モバイル画面サイズ **1,167 ms** で、3,000 msの失敗基準を満たした。コンソールのログインには検証専用の期限付きDBセッションを使った。これはIdPログインの検証とは別で、上記FlashのOIDC検証では実際にIdPへログインした。サービスを変更しながら並行して画面を検証した試行は失敗したため、最終の画面確認は依存するサービス更新が完了してから実行した。

[GitHub Actionsの実VPN・Chromium検証](https://github.com/IPA-CyberLab/IPA-RS-HeteroNetwork/actions/runs/37302126238) も現在の構成で成功した。Actions VMがHeteroNetworkへ参加し、VPN経由で内部コンソールを **856 ms**、6つのゲートウェイの80／9781ポートを **383–615 ms** で開いた。実IdPログイン、再読み込み・新規タブでの認証維持も通過し、Grafana／Prometheusは各3アドレスでHTTP 200を返した。経路収束には12,807 msかかった。参加直後の経路収束時間と、収束後の画面表示時間は区別して記録した。検証後のVPNクライアント削除も成功した。

## 修正と運用上の範囲

Gateway CRDがシークレット参照の `group` と `kind` を補うことで、参照比較が毎回不一致になり、認証ポリシー更新が繰り返される問題をFlash v0.1.46で修正した。明示的に正規形の参照を生成し、CRDのデフォルト適用を再現する回帰テストを追加した。HeteroCloud v0.1.102では、固定レプリカのOIDCサービスも現在のプロバイダー状態を取得し、設定中のコールバックURLを表示する。

実IdP用の検証は、公開経路のある既存realm内の専用クライアント・ユーザーだけを作成した。realm本体や既存利用者の設定は変更していない。メールアドレスをユーザー名にするrealm設定と、モバイルで選択UIが変わるコンソール表示に合わせて検証コードを修正した。以前のGateway構成更新中のInfrastructure acceptanceには失敗が残っているが、上記の最終実行はリトライせず成功した。

タスクIAMはHeteroCloud APIの認証であり、AWSのIMDS／AWS SDKとの互換機能ではない。終了したPodのJWTによる新規交換は拒否するが、Pod終了だけの場合、交換済みAPIトークンは最大15分残る。即時失効にはサービス停止、ロール解除、アカウント無効化を使う。OIDC機能はIdPログインを要求し、アプリケーション固有のユーザー・グループ認可はアプリケーションで扱う。

既存5つの利用者PodはUID・配置ノード・再起動回数・上限・PVCを維持した。保護対象の稼働Podのメモリー上限10 GiBも維持した。ワークロード用ヘルパーイメージはv0.1.41のままとし、利用者コンテナの再起動を生じさせていない。

検証用Flashサービス、VPC、IdPクライアント・ユーザー、2つの組織、IAM設定・キー・トークン、4つの使用量レコード、専用PostgreSQL DBを削除した。残存確認は0件。JWT、Cookie値、パスワード、シークレット、DB接続文字列、復旧アーカイブは検証成果物へ含めない。[機密値を除いた結果](task-iam-oidc-2026-10-05.json) に確認項目と配置状態を記録した。
