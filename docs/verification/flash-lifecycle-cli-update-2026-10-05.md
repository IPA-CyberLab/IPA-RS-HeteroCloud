# Flash lifecycle and CLI updates — 2026-10-05

Flash services now have explicit stop/start operations in the API, CLI and console. Stopping removes running replicas and the HPA while retaining the service ID, desired configuration, VPC membership, secret references and persistent `/root` volume. Starting restores the configured replica count before handing scaling back to the HPA. A stopped service stays stopped when it receives requests. Allocation reservations remain; runtime usage stops after all replicas drain.

This adds lifecycle control to an existing Flash service. It does not add an independent RunTask/StopTask resource, privileged containers, or a configurable persistent-home mount. The persistent mount is `/root`; an image that writes its workspace only to `/home/coder` needs its home redirected to `/root` to retain that data.

The CLI has `heterocloud update`, `update --check` and `update --force`. It selects a complete stable release for the native OS/CPU, verifies SHA-256 and the executable version, then replaces the installed binary. Configuration and credentials are retained. Normal command notices use stderr after execution, preserve stdout/exit status, cache successful checks for six hours and retry failed checks after five minutes. `HETEROCLOUD_NO_UPDATE_CHECK=1` disables automatic checks. Releases are fetched with a separate unauthenticated HTTPS client.

Existing clients without the update command need one manual replacement with a current release.
