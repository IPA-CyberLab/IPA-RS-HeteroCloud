# VPC / Flash 実環境E2E — 2026-10-03

HeteroCloud 0.1.93、CLI 0.1.93、Flash 0.1.41、VPC 0.1.3を本番へ反映し、21項目のE2Eに成功しました。[機械可読の検証記録](vpc-2026-10-03.json)に結果とCIのURLを保存しています。

- API・CLIでのVPC作成・取得・更新・削除。
- 親のAPIキーをシークレットの環境変数として渡し、親から非公開の子コンテナを作成。子へのキーの自動継承なし。
- 内部DNS、TCP・UDPの通信許可、サービスID・グループ単位の制御。
- 未許可ポート・グループ・別VPC・別組織への接続を拒否。未許可グループへのAPI操作も拒否。
- NATの有効化・無効化、コンテナ側の送信無効化、通信ルールの取り消し。
- 内部向けの子に公開ルートがないこと、使用中VPCの削除拒否、リソースとシークレットの削除。
- 本番APIを使うChromiumで、VPCデータ表示までPC 1,539ms・モバイル1,142ms。JavaScriptエラー・横方向のはみ出しなし。

親の配置先はichikawap1、NATの出口はuc-k8sp5でした。公開HTTPSの観測先から返された送信元IPv4は出口ノードと一致しました。追加で親Pod内から公開アセット678,136バイトを取得し、外側で取得した同一アセットとSHA-256が一致しました。

CIではRust・PostgreSQL・CLI・コンソール・Chromiumの既存チェックに加え、隔離したLinuxネットワーク名前空間で、NATの通常経路への迂回拒否、許可の期限切れ、guard再起動、CNIとの送信元保持、ゲートウェイのルール順序変更時の送信制限を検証しました。

Terraformの最終planは変更ゼロ、関連するArgo CDの4アプリケーションはSynced / Healthyです。テスト用のKubernetesリソース、組織、APIキー、ブラウザー用ユーザーとセッションは削除済みです。記録にキー、cookie、DB接続情報、シークレット値は含めていません。

ブラウザーは使い捨ての検証用セッションを使用しており、IDプロバイダーの対話ログインを検証したものではありません。NATはIPv4でゲートウェイノードの出口IPを使います。独自・重複CIDR、固定EIP、IPv6 NATの機能はありません。

再現方法は [scripts/e2e/README.md](../../scripts/e2e/README.md)、利用方法は [VPCとFlashのプライベート接続](../networking/vpc.md) を参照してください。
