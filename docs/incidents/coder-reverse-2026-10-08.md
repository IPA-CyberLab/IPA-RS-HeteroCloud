# Reverse workspace provisioning incident, 2026-10-08

`mizuame/Reverse` failed Terraform plan while refreshing its existing Flash service through the Coder host's task-IAM bridge at `127.0.0.1:7081`. The bridge was still listening. The same GET later returned HTTP 200 repeatedly; the first retry build successfully planned and applied without recreating or destroying the Flash service. The provider had HTTP retry count zero. The failed build retained only the provider's “giving up after 1 attempt” error, so the original upstream status and immediate trigger cannot be established from that record.

Recovery exposed a second, confirmed failure: after the Coder public hostname migration, the managed template variable `coder_url` still held the old Flash hostname. The template replaced that old literal in `coder_agent.main.init_script`; the newly generated script instead contained `https://coder.mizuame.app`, so rewriting did not occur. The workspace tried downloading the agent from the new public hostname, whose origin addresses are protected by the VPC's outbound rules. The download failed and the agent never connected. The previous domain migration verified the sign-in page, but did not verify a stopped workspace restart. That incomplete migration verification missed this dependency.

The deployed template now rewrites the bootstrap using `data.coder_workspace.me.access_url`, which tracks the current deployment URL, into `coder_private_url`. A precondition rejects a bootstrap without the private URL. `CODER_AGENT_URL` continues using the existing private VPC endpoint. Network protections were retained. Managed compatibility input `coder_url` was updated too.

The REST provider now makes up to three bounded retries for transient connection/server failures, preserving the 60-second per-request timeout. The existing API's unique service name prevents duplicate service allocation; the recovery kept the existing resource ID. A standalone loopback test returned HTTP 503 twice and then succeeded: four GETs and no mutations were observed. The retry settings do not constitute an exactly-once guarantee for interrupted mutations.

Template import validated the actual provider schemas before activation. Build 5 then completed with 0 resources added, 1 updated and 0 destroyed. The same Flash service and `/root` PVC were retained. The agent reached `connected/ready`, both VS Code and File Browser reported healthy, and code-server's local health endpoint returned HTTP 200. Authenticated Chromium displayed the running workspace and IDE link using a temporary maintenance token. The dashboard also queried the optional Docker container listing; that endpoint returned HTTP 500 on this workspace without a Docker daemon. This did not prevent the workspace or IDE from running.

The live template source and provider lock are now tracked in [examples/coder](../../examples/coder/README.md). [Sanitized verification](coder-reverse-2026-10-08.json) includes the deployed version and build IDs. Credentials, agent tokens, complete Terraform state and raw secret-bearing logs are excluded. Temporary maintenance credentials were removed after verification.
